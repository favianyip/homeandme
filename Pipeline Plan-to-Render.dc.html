Home & Me — Plan → 3D → Render Pipeline

SYSTEM BRAINSTORM

Floor plan → detection → 3D sketch → render

Six stages. One JSON contract in the middle that every stage reads and writes — detection improves, sketching improves, rendering improves, independently. Chips show what already runs on the platform today.

01 · INGEST & NORMALIZELIVE

Accept a phone photo, PDF page or scan. Fix rotation, deskew off the dominant wall angle, adaptive threshold, despeckle.

On platform: PlanIntake upload + preprocessing in journey-vision. Add later: PDF page picker, multi-page sale packs.

02 · DETECT INKLIVE

Cascade, cheapest first: classical CV (threshold + morphology) → learned wall classifier (AUC 0.89) on ambiguous sheets → LLM vision as referee for semantics.

Walls, room regions (flood fill), doors (gap + swing arc), windows (double-line — the known weak spot). Later: proper segmentation net server-side, trained on the corpus.

03 · SCALE & NAMELIVE

Read printed dimensions (digit OCR) and the HDB title-block code (445 = New Flat, 452 = Model A…), reconcile both against the archetype library.

Room naming: 12-feature classifier + LLM cross-check. Fallbacks, in order: door-width prior (~0.85 m) → user two-click calibration.

04 · VECTORIZE → CONTRACTNEXT

Raster wall mask → centerlines → snap to orthogonal polylines → room polygons with shared edges. Output is the plan JSON below — the single contract everything downstream consumes.

Snap exists today; shared-edge cleanup and topology validation (every room closed, every opening on a wall) are the next build.

05 · 3D SKETCHLIVE

Extrude walls 1:1 from the traced ink to 2.6 m, cut door and window holes, lay floor slabs per room. Orbit freely in the Studio.

Customer confirms here — drag a wall, rename a room — before anything renders. Confirmed traces feed the corpus (training loop).

06 · RENDER HANDOFFNEXT

Export the confirmed scene as glTF/GLB + the contract JSON + a theme id, push to a render lane (three options, right below).

Geometry stays the ground truth — whichever renderer runs, it renders this flat.

THE CONTRACT — plan.json

{
  "units": "m",
  "source": { "kind": "hdb", "code": "445", "confidence": 0.92 },
  "scale": { "px_per_m": 41.2, "method": "ocr+archetype" },
  "walls": [ { "a": [0,0], "b": [3.2,0], "t": 0.15, "h": 2.6 } ],
  "openings": [ { "wall": 0, "type": "door", "at": 1.1, "w": 0.85 } ],
  "rooms": [ { "label": "LIVING", "poly": [[0,0],[3.2,0],[3.2,4.1],[0,4.1]], "area": 13.1 } ],
  "theme": "scandi-01",
  "cameras": [ "living-corner", "kitchen-wide" ]
}

Versioned, tiny, human-readable. Detection writes it, the Studio edits it, renderers and the quote engine only ever read it.

RENDER LANE A — INTERACTIVELIVE

three.js materials + theme packs in the Studio. Instant, free, orbitable — this is the sales floor. Every other lane is an upgrade on top of it.

RENDER LANE B — PHOTOREAL CGILATER

Headless Blender/Cycles on a server queue eats the glTF, applies a material library, renders the camera list. True lighting; minutes per shot; predictable. Good for the final proposal PDF.

RENDER LANE C — AI RENDERNEXT

Capture the Studio viewport + its depth map, run image-to-image with structure control (depth/edge-guided diffusion) per theme. Seconds per shot — this is the homepage's "photoreal previews of your flat" promise. Geometry from the contract keeps it honest; needs a GPU API server-side.

WHERE IT PLUGS INTO THE PLATFORM

Assistant chat — attach plan→ PlanIntake — verify + upload→ PlanDetect — stages 01–04→ Studio — sketch, confirm, themes→ /api/render — queue (future)

Today the whole pipeline runs in the browser. At launch, stages 02–04 and both heavy render lanes move behind your server (/api/detect, /api/render) — keys and models server-side — while the Studio stays client-side. Every customer-confirmed trace flows back into the corpus, so detection gets better with every job.
